# watermarks-remover — Installations- und Funktionsprüfung

Geprüft am 2026-08-25 gegen `guillaumemeyer/watermarks-remover` @ `4a0fbc3` (main).

## Installation

Vor der Ausführung wurde `install_skill.py` geprüft: reiner Datei-Kopierer
(`copytree`/Symlink mit Backup), keine Netzwerk- oder `exec`-Aufrufe. Der
Service ist stdlib-only.

```bash
python3 install_skill.py --skill remove-ai-marks         --target claude-code
python3 install_skill.py --skill clean-user-facing-text  --target claude-code
python3 service/scripts/server.py --host 127.0.0.1 --port 8765
```

Beide Skills liegen unter `~/.claude/skills/` und werden von Claude Code als
`remove-ai-marks` und `clean-user-facing-text` geladen.

**Nicht installiert:** der mitgelieferte `PostToolUse`-Hook (`hooks/hooks.json`).
Er würde jede vom Agenten geschriebene Datei automatisch auf Provenance-Marks
prüfen bzw. diese in-place entfernen. Das war nicht Teil der Anfrage und sollte
eine bewusste Entscheidung sein, deshalb bewusst ausgelassen.

## Gefundener Fehler: `/inspect` übersieht Layer A in OOXML

`/inspect` meldet eine DOCX-Datei mit 3 ZWSP im Fließtext (und sonst nichts) als
unauffällig, während `/clean` daraus 3 Zeichen entfernt:

```
/inspect: suspicious=False  suspicious_total=0  findings=[]
/clean  : ['layer A text: removed=3 replaced=0']
```

Isoliert in `corpus/zw_only.docx`. Wer `/inspect` als Audit-Gate nutzt, bekommt
hier ein falsches „sauber". Betrifft nur die Prüfung, nicht die Bereinigung.
Im Upstream existiert dazu der offene Branch `fix/74-layer-a-docx-odt`.

## Layer B (statistische Watermarks) — nicht verifizierbar

Layer B hat keine testbare Implementierung. `SKILL.md` sagt es direkt:

> The service does **not** hold a rewrite model — **you** are the rewrite model.

Der einzige lokale Codepfad ist `rewrite_text.py`, das im Default-Backend
(`print-prompt`) nur einen Paraphrase-Prompt ausgibt — kein Modell, keine
Messung. Es ist kein HTTP-Endpoint; die Umschreibung selbst delegiert das Tool
an ein LLM (Ollama / OpenAI-kompatibel / den Agenten).

Entscheidend: sämtliche `text_detectors` sind `false`. Damit fehlt der
Evaluations-Schleife des Tools der Oracle, gegen den sie prüft — ein
Vorher/Nachher-Ergebnis wäre in dieser Umgebung nicht messbar und damit
aussagelos. Das Repo formuliert Layer B selbst nur als „best-effort" ohne
Undetectability-Garantie.
